# プランニングポーカーアプリケーション仕様書 Rev.1

## 文書管理情報

- **文書バージョン**: Rev.1
- **作成日**: 2026-02-04
- **ステータス**: 初版ドラフト

## 1. 概要

### 1.1 目的

本文書は、Webベースのプランニングポーカーアプリケーションの仕様を定義するものである。アジャイル開発チームがストーリーポイントの見積もりを行う際に、リモート・対面問わず円滑なコミュニケーションを実現することを目的とする。

### 1.2 適用範囲

本仕様は以下を対象とする：

- Webアプリケーションのユーザーインターフェース
- ルーム管理機能
- 投票機能
- チャット・コミュニケーション機能

## 2. システム概要

### 2.1 基本コンセプト

プランニングポーカーアプリケーションは、複数の参加者がリアルタイムでストーリーポイントを投票し、同時にリベール（公開）することで、チーム全体でコンセンサスを形成するためのツールである。

### 2.2 主要機能

1. **ルーム管理**: URL単位でルームを作成・管理
2. **投票機能**: 参加者による秘密投票とリベール
3. **チャット機能**: トピック単位での会話ログ管理
4. **参加者管理**: ニックネームベースの識別とパスコード認証
5. **ロール・状態管理**: 投票者/観察者ロールと離席中状態

## 3. 機能要件

### 3.1 プラットフォーム対応

#### 3.1.1 対応デバイス・ブラウザ

本アプリケーションは以下のモダンブラウザをサポート対象とする：

**PC（デスクトップ）:**
- Windows/Mac/Linux
- Chrome（最新版および1つ前のバージョン）
- Edge（最新版および1つ前のバージョン）
- Firefox（最新版および1つ前のバージョン）
- Safari（最新版および1つ前のバージョン）

**モバイル:**
- iOS（iPhone/iPad）: Safari（最新版および1つ前のバージョン）
- Android: Chrome（最新版および1つ前のバージョン）

### 3.2 ルーム管理

#### 3.2.1 ルームの作成

- ルーム作成時にルーム名を入力
- ルーム作成時に一意のURLを自動生成
- URL形式: `https://[domain]/[room-id]`
- room-idは推測困難なランダム文字列（例: UUID）

#### 3.2.2 参加者の招待

- 生成されたURLを参加者に共有することで入室を促す
- URLの共有手段は任意（Slack、メール、チャット等）
- ルーム作成者が特別な権限を持つことはない（フラットな権限構造）

#### 3.2.3 ルーム名

- ルーム作成時に任意のルーム名を設定可能
- ルーム名は参加者全員に表示される
- ルーム名は見積もり対象やプロジェクト名などを設定することを想定
- 例: "スプリント24見積もり"、"プロジェクトX バックログ整理"

### 3.3 参加者管理

#### 3.3.1 ニックネーム識別

- 入室時にニックネームを入力
- 同一ルーム内でニックネームの一意性を保証
- 大文字小文字は区別する

#### 3.3.2 パスコード機能

入室時の動作：

1. ニックネーム入力
2. システムが6桁の数字パスコードを自動生成（例: 123456）
3. パスコードを参加者に表示（入室成功画面に常時表示、またはメニュー/ボタンからいつでも確認可能）
4. パスコードは画面内で常にアクセス可能とし、参加者がいつでも確認できるようにする
5. ただし、「再接続が必要な状況では確認できない可能性が高いため、パスコードは記録しておいてください」と常に案内する

#### 3.3.3 重複ニックネーム処理

同一ニックネームでの入室試行時：

**標準動作（パスコード未入力）:**
- 「すでに同じニックネームのユーザーが参加しています」と表示
- 「再接続をしたい場合はパスコードを入力してください」とメッセージ表示
- 入室画面に戻り、以下の操作を行う：
  - パスコード入力フィールドを可視化
  - パスコード入力フィールドを強調表示
  - パスコード入力フィールドにフォーカスを当てる
- パスコード未入力の場合は入室を拒否

**パスコード入力時:**
- 入力されたパスコードが既存クライアントのパスコードと一致する場合：
  - 既存のクライアントセッションを無効化
  - 新しいクライアントセッションを有効化（再接続として扱う）
  - 「再接続しました」のメッセージを表示
- パスコードが不一致の場合：
  - 入室を拒否
  - 「パスコードが正しくありません」と表示

**セキュリティポリシー:**
本アプリケーションは、参加者間の軽量な識別を目的としており、厳密なユーザー認証は実装しない。パスコードによる同一ユーザー検証はゆるいセキュリティレベルで運用する。プランニングポーカーという用途の性質上、悪意のある第三者による攻撃を想定したセキュリティ対策は行わない。

#### 3.3.4 参加者ロール

以下のロールを用意し、参加者は任意のタイミングで制限なくロールを変更可能とする：

1. **投票者（Voter）**
   - デフォルトロール
   - 投票可能
   - リベール・リセット操作可能
   - チャット参加可能

2. **観察者（Observer）**
   - 投票不可
   - 他の参加者の投票状況・結果を閲覧可能
   - リベール・リセット操作可能
   - チャット参加可能

#### 3.3.5 参加者状態

ロールとは別に、参加者の状態を表示する機能を提供する：

- **通常**: デフォルト状態
- **離席中（Away）**: 参加者が一時的に席を外していることを他の参加者に伝える
- 状態は参加者自身がいつでも変更可能
- 離席中の参加者も投票やチャットは可能（制限はない）
- 他の参加者には、参加者一覧で離席中のアイコンまたはラベルが表示される

### 3.4 投票機能

#### 3.4.1 ポイントスケール

以下のポイントを選択可能とする（フィボナッチ数列ベース）：

- 0, 1, 2, 3, 5, 8, 13, 21, 34+
- 特殊カード: "?"（不明）, "☕"（休憩）

**注意:** 34+ は表記上は「34+」と表示するが、内部的には 34 として扱う。

#### 3.4.2 投票フロー

**リベール前（秘密投票フェーズ）:**
1. 各参加者が自分のポイントを選択
2. 選択したポイントは本人にのみ表示
3. 他の参加者には「投票済み」または「未投票」のステータスのみ表示
4. 投票を変更可能（何度でも）

**リベール操作:**
- どの参加者でも「リベール」ボタンをクリック可能
- リベールすると全参加者の投票が一斉に公開される

**リベール後（公開フェーズ）:**
1. 全参加者の投票結果が表示される
2. この時点での投票変更は即座に他の参加者に反映される
3. リアルタイム更新により、変更が即時に共有される

#### 3.4.3 リセット機能

- どの参加者でも「リセット」ボタンをクリック可能
- リセットにより以下が実行される：
  - 全参加者の投票をクリア
  - 秘密投票フェーズに戻る
  - 新しい「トピック」が開始される（チャット履歴の区切りに影響）

### 3.5 視覚表現

#### 3.5.1 リベール前の表示

- 自分の投票: ポイント数値をそのまま表示
- 他の参加者:
  - 投票済み: チェックマーク ✓ またはカードの背面イメージ
  - 未投票: 空のカードまたは "−" 表示

#### 3.5.2 リベール後の表示

ポイントの大きさを視覚的に表現：

**方法1: カードサイズ**
- ポイントが大きいほどカードサイズを大きく表示
- 例: 1pt（小）、13pt（中）、34+（大）

**方法2: 色分け**
- 低ポイント（0-2）: 緑系
- 中ポイント（3-8）: 黄色系
- 高ポイント（13-21）: オレンジ系
- 超高ポイント（34+）: 赤系

#### 3.5.3 統計情報の表示

リベール後は以下の統計情報も表示する：

- 平均値、中央値、最頻値
- 最小値・最大値
- 合意度（標準偏差等）

### 3.6 チャット機能

#### 3.6.1 基本機能

- リアルタイムテキストチャット
- 全参加者が発言可能（観察者含む）
- タイムスタンプ付きメッセージ表示
- 発言者のニックネーム表示

#### 3.6.2 トピック単位の履歴管理

**トピックの概念:**
- 1回のリセットから次のリセットまでを1つの「トピック」とする
- 各トピックは見積もり対象（ストーリー、タスク等）に対応

**トピックタイトル:**
- 各トピックには任意でタイトルを設定可能
- トピックタイトルは手動で入力するオプショナルなテキストボックスで入力
- いつでも変更可能
- リセット時にダイアログは表示しない
- 自動抽出は行わない

**トピックごとの情報:**
- チャット履歴
- 最終的な投票結果
- トピックタイトル（設定されている場合）
- 開始時刻・終了時刻（リセットまたはルーム終了）

**履歴の利用:**
- 過去のトピックを参照可能
- 「トピック1」「トピック2」...と番号で管理
- 任意のトピックにタイトル付与可能（例: "US-1234: ユーザーログイン機能"）

#### 3.6.3 プランニング対象の共有

チャットでの共有を想定する情報：
- チケット識別子（例: JIRA-1234、GitHub Issue #123）
- チケットURL
- 要件・仕様の概要
- 技術的な懸念事項
- 見積もりの根拠

### 3.7 リアルタイム通信

本アプリケーションはリアルタイム双方向通信を必要とする。具体的な技術選定は仕様確定後の技術選定フェーズで行う。

#### 3.7.1 要件
- 参加者の入退室をリアルタイムで通知
- 投票状況の変化をリアルタイムで反映
- チャットメッセージの即時配信
- ロール変更・状態変更のリアルタイム反映

#### 3.7.2 接続断時の挙動

- 一時的な接続断時は自動再接続を試行
- 再接続成功時は現在の状態を復元
- 長時間の接続断後は再入室（パスコード使用）を促す

## 4. 非機能要件

### 4.1 パフォーマンス（案・仕様確定後に再検証）

- 初回ページ読み込み: 3秒以内
- 投票反映の遅延: 500ms以内
- チャットメッセージ配信遅延: 1秒以内
- 同時接続ユーザー: ルームあたり最大50名を想定

### 4.2 セキュリティ

- HTTPS通信の必須化
- room-idの推測困難性確保
- パスコードによる再接続認証（ゆるいセキュリティレベル）
- XSS・CSRF対策の実装

### 4.3 可用性

- ルームデータの永続化（サーバー再起動時も維持）
- データ保持期間: 最終アクティビティから24時間

### 4.4 ユーザビリティ

- 直感的なUI/UX設計
- レスポンシブデザイン対応
- アクセシビリティ対応（WCAG 2.1 AA準拠を推奨）
- ダークモード対応

## 5. ユーザーインターフェース

### 5.1 画面構成

#### 5.1.1 ランディングページ（ルーム作成画面）
- ルーム名入力フィールド
- 新規ルーム作成ボタン
- URL経由での参加のみをサポート（個別のroom-id入力フィールドは設けない）

#### 5.1.2 入室画面
- ニックネーム入力フィールド
- ロール選択（投票者/観察者）
- パスコード入力フィールド（初期状態では非表示）
  - 「再接続」等のリンク/ボタンをクリックするとフィールドが表示される
  - 重複ニックネーム検出時は自動的に表示・強調される

#### 5.1.3 メイン画面

**レイアウト:**
- 上部: ルーム情報（ルーム名、参加者数）
- 中央: 参加者一覧と投票状況（各参加者のロールと状態も表示）
- 下部: 自分の投票パネル（ポイントカード選択）
- 右側または下部: チャットエリア
- 操作ボタン: リベール、リセット
- ユーザー設定: ロール変更、状態変更（離席中切り替え）
- パスコード表示: 常時表示またはメニュー/ボタンから確認可能

### 5.2 レスポンシブデザイン

**PC（デスクトップ）:**
- 横長レイアウト
- 参加者一覧とチャットを左右または上下に配置

**モバイル（スマートフォン）:**
- 縦長レイアウト
- タブまたはスワイプで投票エリアとチャットを切り替え

**タブレット:**
- 画面サイズに応じてPCまたはモバイルレイアウトを適用

## 6. データモデル（案・仕様確定後に再検証）

### 6.1 ルーム（Room）

```
Room {
  roomId: string (UUID)
  roomName: string
  createdAt: timestamp
  lastActivityAt: timestamp
  participants: Participant[]
  currentTopic: Topic
  topicHistory: Topic[]
}
```

### 6.2 参加者（Participant）

```
Participant {
  nickname: string
  passcode: string (6-digit)
  role: "voter" | "observer"
  status: "normal" | "away"
  connectionStatus: "connected" | "disconnected"
  connectedAt: timestamp
}
```

### 6.3 トピック（Topic）

```
Topic {
  topicId: number (sequential)
  title: string (optional)
  startedAt: timestamp
  endedAt: timestamp (optional)
  isRevealed: boolean
  votes: Vote[]
  chatMessages: ChatMessage[]
}
```

### 6.4 投票（Vote）

```
Vote {
  participantNickname: string
  point: 0 | 1 | 2 | 3 | 5 | 8 | 13 | 21 | 34 | "?" | "☕"
  votedAt: timestamp
  updatedAt: timestamp
}
```

### 6.5 チャットメッセージ（ChatMessage）

```
ChatMessage {
  messageId: string (UUID)
  participantNickname: string
  message: string
  timestamp: timestamp
}
```

## 9. 懸念事項

### 9.1 技術的懸念

1. **リアルタイム通信のスケーラビリティ**
   - 大量の同時ルームが発生した場合の負荷対策
   - WebSocket接続数の上限
   - 対策: ロードバランサー、水平スケーリング、WebSocket専用サーバーの検討

2. **モバイルデバイスでのWebSocket接続安定性**
   - バックグラウンド移行時の接続維持
   - ネットワーク切り替え時の再接続
   - 対策: ハートビート機能、自動再接続ロジックの実装

3. **ルームデータの永続化方法**
   - メモリ内データストア（Redis）のみか、RDBMSとの併用か
   - データ保持期間の管理方法

### 9.2 UX/UI懸念

1. **モバイルでの操作性**
   - 小さい画面でポイント選択やチャット入力がしやすいか
   - 対策: タッチフレンドリーなUI設計、適切なフォントサイズ

2. **リベール前後の状態遷移の明確さ**
   - ユーザーが現在どのフェーズにいるかを視覚的に理解できるか
   - 対策: 明確な状態表示、色分け、アニメーション

3. **ロールと状態の使い分けの明確さ**
   - 投票者/観察者ロールと、通常/離席中状態の違いをユーザーが理解できるか
   - 対策: 明確なラベリング、ヘルプテキスト

### 9.3 セキュリティ懸念

**本アプリケーションは軽量な認証を採用しており、以下のセキュリティ懸念は受容する：**

1. **パスコード6桁の安全性**
   - 総当たり攻撃のリスク（1,000,000通り）
   - 本アプリの性質上、ゆるいセキュリティレベルで運用
   - 悪意のある攻撃は想定しない

2. **room-idの推測可能性**
   - UUID v4を使用すれば十分な強度があると判断
   - 対策: UUID v4またはそれに準ずるランダム生成

3. **チャットメッセージの検証**
   - XSS攻撃への対策
   - 対策: サニタイゼーション、CSP（Content Security Policy）

### 9.4 運用懸念

1. **古いルームのクリーンアップ**
   - いつ、どのようにルームデータを削除するか
   - 対策: 定期的なバッチジョブ、TTL（Time To Live）設定

2. **監視・ロギング**
   - エラー検知、パフォーマンス監視の方法
   - 対策: APMツール導入、構造化ログ

3. **ユーザーサポート**
   - 問い合わせ対応の体制
   - FAQの整備

## 付録 A: 用語集

- **プランニングポーカー**: アジャイル開発手法の一つで、チームメンバーがストーリーポイントを見積もる際に使用する手法
- **ストーリーポイント**: ユーザーストーリーやタスクの相対的な大きさを表す単位
- **リベール**: 参加者全員の投票を一斉に公開する操作
- **ルーム（Room）**: プランニングポーカーを実施する仮想的な「部屋」。従来は「セッション」と呼ばれることもあるが、本仕様では用語の混乱を避けるため「ルーム」に統一
- **トピック（Topic）**: 1回の見積もり対象（リセット間の期間）
- **フィボナッチ数列**: 0, 1, 1, 2, 3, 5, 8, 13, 21...と続く数列。プランニングポーカーでポイントスケールとして使用される
- **投票者（Voter）**: 投票可能な参加者ロール
- **観察者（Observer）**: 投票はせず、閲覧のみ行う参加者ロール
- **離席中（Away）**: 参加者が一時的に席を外していることを示す状態
